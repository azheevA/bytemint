# ByteMint — портал инструментов для разработчиков

ByteMint — англоязычный сайт с бесплатными браузерными инструментами. Он задуман как небольшой продукт для привлечения органического трафика и последующей монетизации рекламой, партнёрскими рекомендациями и собственными цифровыми товарами.

**Важно:** сайт сам по себе не создаёт пассивный доход. Для заработка нужны посетители, полезные материалы, одобренные рекламные/партнёрские аккаунты и постоянное улучшение продукта. В архиве нет выдуманных партнёрских ссылок, платёжных ключей или обещаний доходности.

## Что уже реализовано

- JSON Formatter & Validator — форматирование, минификация и проверка JSON.
- JWT Decoder — просмотр заголовка и payload JWT. Подпись токена не проверяется.
- Base64 Encoder & Decoder — кодирование и декодирование UTF-8.
- UUID Generator — генерация UUID v4.
- Text & Word Counter — подсчёт слов, символов, строк и примерного времени чтения.
- Главная, каталог инструментов, пять полноценных руководств в разделе Guides, отдельные SEO-страницы инструментов, About, Contact, Privacy, Terms и Affiliate Disclosure.
- Sitemap, robots.txt, canonical URL, Open Graph и метаданные страниц.
- Необязательные рекламные, партнёрские и внешние checkout-блоки.
- Форма обратной связи через Resend с Zod-валидацией и ограничением частоты запросов через Upstash Redis.

## Стек

- Next.js 16.4.5, App Router
- React 19, TypeScript с `strict: true`
- Zod 4 — серверная валидация
- Upstash Redis + `@upstash/ratelimit` — распределённый rate limit
- Resend — отправка сообщений с формы контактов
- Vitest — unit-тесты
- ESLint, GitHub Actions, Dependabot
- Docker multi-stage, Docker Compose

## Архитектура

```text
src/
  app/
    api/contact/          API-обработчик обратной связи
    tools/                Каталог и статические страницы инструментов
    guides/               Каталог и статические страницы руководств

    contact/              Контакты
    privacy/               Политика конфиденциальности
    terms/                 Условия использования
  components/              Общие UI-компоненты
  config/                  Настройки сайта и монетизации
  features/tools/          Реестр инструментов, логика обработки, тесты

```

В MVP нет базы данных, регистрации, авторизации, загрузки файлов и пользовательских сессий: этим инструментам они не нужны. Это уменьшает поверхность атаки, стоимость хостинга и объём персональных данных.

## Локальный запуск

Требуется Node.js 22+ и npm.

PowerShell:

```powershell
Copy-Item .env.example .env
npm install
npm run dev
```

Открой `http://localhost:3000`.

Проверки качества:

```powershell
npm run lint
npm run typecheck
npm run test
npm run build
```

В исходном архиве нет `package-lock.json`: среда, в которой готовился проект, не имела доступа к npm registry. Выполни `npm install` на своём компьютере и добавь созданный `package-lock.json` в Git. Это обязательный шаг: CI и Docker намеренно используют только `npm ci` и завершаются ошибкой, если lock-файла нет. Так сборка не будет незаметно устанавливать плавающие версии зависимостей.

## Переменные окружения

Скопируй `.env.example` в `.env`. Не добавляй серверные секреты в переменные с префиксом `NEXT_PUBLIC_`.

| Переменная | Назначение |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | Публичный HTTPS-адрес сайта; используется в canonical, sitemap и robots |
| `NEXT_PUBLIC_ADSENSE_CLIENT` | ID издателя AdSense, только после одобрения |
| `NEXT_PUBLIC_ADSENSE_SLOT_TOP` | ID рекламного блока AdSense |
| `NEXT_PUBLIC_AFFILIATE_HOSTING_URL` | Одобренная партнёрская ссылка на хостинг |
| `NEXT_PUBLIC_AFFILIATE_AI_URL` | Одобренная партнёрская ссылка на AI-сервис |
| `NEXT_PUBLIC_PREMIUM_PRODUCT_URL` | Внешняя страница оплаты/продажи собственного цифрового продукта |
| `RESEND_API_KEY` | Серверный API-ключ Resend |
| `CONTACT_TO_EMAIL` | Куда отправлять сообщения |
| `CONTACT_FROM_EMAIL` | Подтверждённый адрес отправителя в Resend |
| `UPSTASH_REDIS_REST_URL` | URL Upstash Redis REST API |
| `UPSTASH_REDIS_REST_TOKEN` | Секретный токен Upstash |
| `RATE_LIMIT_HASH_SECRET` | Случайный секрет длиной минимум 32 символа для HMAC-хеширования IP |

Секрет для rate limit можно сгенерировать в PowerShell:

```powershell
node -e "console.log(require('crypto').randomBytes(48).toString('base64'))"
```

### Форма обратной связи

Чтобы контакты работали в production:

1. Создай аккаунт Resend и подтверди собственный домен отправителя.
2. Укажи `RESEND_API_KEY`, `CONTACT_FROM_EMAIL` и `CONTACT_TO_EMAIL`.
3. Создай базу Upstash Redis и укажи её URL и токен.
4. Сгенерируй `RATE_LIMIT_HASH_SECRET`.
5. Перезапусти/пересобери приложение и проверь валидное сообщение, неверные поля, чужой Origin, большой запрос и частые отправки.

Лимит — 4 сообщения за скользящее 10-минутное окно на IP. В production идентификатор IP перед сохранением в Redis хешируется через HMAC. При отсутствии Upstash или HMAC-секрета production-форма закрывается с ошибкой конфигурации — локальный in-memory лимитер не используется для serverless production.

## Монетизация

### Реклама

Реклама выключена, пока не указаны одновременно ID издателя и ID рекламного блока. Сначала опубликуй сайт на собственном домене, добавь оригинальные руководства и примеры, проверь актуальные правила AdSense и только затем подавай заявку. Если AdSense попросит `ads.txt`, добавь точную запись издателя, выданную в кабинете, в `public/ads.txt`.

До показа рекламы в регионах, где это требуется, подключи сертифицированную CMP-платформу и обнови Privacy Policy под фактический сценарий согласия и рекламные технологии.

### Партнёрские ссылки

Вставляй только реальные ссылки программ, которые приняли заявку. Сайт принимает только HTTPS URL, выводит раскрытие партнёрских отношений рядом с блоком рекомендаций и использует `rel="sponsored nofollow noopener noreferrer"`.

### Собственный цифровой продукт

Можно продавать Next.js starter kit, UI-компоненты, шаблоны API-валидации, Docker/CI starter или другой оригинальный материал. Оплату и выдачу файлов лучше поручить внешнему checkout-провайдеру, доступному в твоей стране. Проект не хранит данные банковских карт и не реализует платёжную систему. Укажи готовую страницу товара в `NEXT_PUBLIC_PREMIUM_PRODUCT_URL`.

## Валидация и безопасность

- Контактная форма проверяется на сервере через строгую Zod-схему; неизвестные поля запрещены.
- Проверяются тип контента, обязательный в production same-host Origin, размер тела запроса (10 КБ), длина и формат полей. Проверка сравнивает Origin с `Host` и не доверяет `x-forwarded-host`.
- Запрос читается потоково с ограничением размера, а не целиком без лимита.
- Honeypot и распределённый Upstash rate limit (4 запроса за 10 минут) уменьшают простой спам. Для идентификации клиента предпочтителен `x-real-ip`; reverse proxy должен перезаписывать этот заголовок, а приложение нельзя открывать напрямую в обход proxy.
- Текст письма отправляется как plain text.
- IP в Redis используется только в HMAC-хешированном виде.
- JSON, JWT, Base64, UUID и подсчёт текста обрабатываются в браузере. Эти входные данные не отправляются в API ByteMint.
- Размер входа инструментов ограничен.
- UUID v4 создаётся через Web Crypto.
- JWT Decoder только декодирует header и payload; он не подтверждает подлинность токена.
- Base64 — кодирование, а не шифрование.
- В `next.config.ts` заданы CSP, HSTS в production, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy и COOP.
- В CSP внешние домены рекламной сети разрешаются только при включённой конфигурации AdSense.

Перед production дополнительно настрой WAF/бот-защиту хостинга, HTTPS, мониторинг без сбора содержимого инструментов, резервный процесс обработки запросов на удаление данных и юридическую проверку страниц Privacy/Terms для нужных стран. Статическая CSP оставляет `unsafe-inline` для совместимости с bootstrap Next.js; для более строгого режима внедри nonce-based CSP и проверь совместимость со всеми включёнными интеграциями.

## CI/CD

`.github/workflows/ci.yml` запускается на Pull Request и push в `main`. Проверки: `npm ci` из обязательного lock-файла, ESLint, TypeScript, Vitest (включая тесты проверки Origin и размера тела), полный `npm audit` и production build.

`.github/workflows/deploy.yml` повторно проверяет точный commit перед деплоем. Автоматический деплой возможен только после успешного CI для `main`; ручной запуск также разрешён только из `main` и не пропускает проверки. Для включения деплоя:

- Repository Variable: `VERCEL_DEPLOY_ENABLED=true`
- Repository Secrets: `VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`
- Production environment variables нужно настроить в Vercel.

Защити ветку `main` и сделай успешный CI обязательным status check. CI не заменяет проверку staging и production smoke test.

## Docker

Один раз выполни `npm install`, чтобы создать `package-lock.json`, затем скопируй `.env.example` в `.env`, укажи `NEXT_PUBLIC_SITE_URL` и запусти:

```powershell
docker compose up --build -d
docker compose logs -f web
```

В Docker публичные `NEXT_PUBLIC_*` переменные передаются как build args: Next.js встраивает их в клиентский bundle на этапе сборки. Контейнер запускается от непривилегированного пользователя и использует standalone output. Для публичного production-доступа нужен HTTPS reverse proxy или managed hosting — не выставляй контейнер напрямую в интернет без TLS и защиты платформы.

## Что сделать перед запуском

- [ ] Указать реальный HTTPS-домен в `NEXT_PUBLIC_SITE_URL`.
- [ ] Выполнить `npm install` и закоммитить `package-lock.json` (без этого CI и Docker намеренно не запустятся).
- [ ] Заменить юридические шаблоны на точные сведения о владельце, сервисах и юрисдикциях.
- [ ] Добавить реальные контакты владельца проекта и процесс обработки privacy-запросов.
- [ ] Развивать пять существующих руководств на основании запросов и статистики Search Console; не размножать тонкие SEO-страницы.
- [ ] Настроить Resend и Upstash, проверить контактную форму.
- [ ] Добавить только одобренные affiliate URL и готовую checkout-страницу.
- [ ] Подать заявку в рекламную сеть после появления полезного контента и аудитории.
- [ ] Подключить CMP, когда этого требуют рекламная сеть или применимое право.
- [ ] Проверить доступность, мобильную версию, Core Web Vitals, Sitemap и индексацию в Search Console.

## Реалистичный план развития

1. Опубликовать пять инструментов и написать пять качественных руководств с реальными примерами и ограничениями.
2. Смотреть запросы и показы в Search Console; усиливать те инструменты, где появляется спрос.
3. Добавлять новые инструменты на основании поискового спроса и отзывов.
4. Подключать партнёрские рекомендации только там, где они полезны посетителю.
5. Создать один оригинальный цифровой товар и проверить спрос до расширения каталога.
6. Ежемесячно смотреть трафик, использование инструментов и реальную выручку; удалять страницы, которые не приносят пользы.
